# Modelado de Amenazas (STRIDE) para Endpoints Migrados

## Metodología
Se aplica el modelo de amenazas **STRIDE** para identificar riesgos de seguridad en los endpoints expuestos mediante Kong API Gateway hacia los microservicios.

## Matriz de Amenazas y Contramedidas

| Categoría STRIDE | Descripción de la Amenaza | Componente Afectado | Contramedida / Mitigación Implementada |
|---|---|---|---|
| **Spoofing** | Suplantación de identidad de usuarios en peticiones hacia microservicios. | Kong Gateway / Microservicios | Validación estricta de tokens JWT/OIDC en Kong; mTLS entre Kong y microservicios. |
| **Tampering** | Modificación no autorizada de la carga útil en tránsito. | Comunicaciones de red | TLS 1.3 obligatorio en todas las conexiones externas e internas. |
| **Repudiation** | Denegación del origen de transacciones sensibles. | Logs / Auditoría | Logs de auditoría centralizados con marcas de tiempo inmutables en Grafana Loki. |
| **Information Disclosure** | Exposición involuntaria de stack traces o cabeceras del servidor. | APIs / Microservicios | Sanitización de respuestas de error en Kong; remoción de cabeceras `Server` y `X-Powered-By`. |
| **Denial of Service** | Saturación del servicio mediante ataques de inundación de peticiones. | Kong Gateway | Configuración de plugins de Rate Limiting y Request Size Limiting en Kong. |
| **Elevation of Privilege** | Invocación de funciones privileged por usuarios no autorizados. | Microservicios | Control de acceso basado en roles (RBAC) y verificación de claims/scopes OAuth2. |
