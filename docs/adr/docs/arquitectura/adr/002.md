# ADR 002: Elección de Kong API Gateway como Puerta de Enlace de la Arquitectura

- **Estado:** Aprobado
- **Fecha:** 2026-09-21
- **Autores:** Equipo de Arquitectura y DevSecOps

## Contexto
Con la adopción del patrón Strangler Fig y la convivencia del monolito con los nuevos microservicios, se requiere un componente centralizado de enrutamiento dinámico, políticas de seguridad, gestión de tráfico y observabilidad.

## Decisión
Seleccionar **Kong API Gateway** como solución estándar para la plataforma:
- Implementar enrutamiento dinámico y balanceo de carga entre el monolito y los microservicios.
- Centralizar la autenticación/autorización con plugins de OAuth2, OpenID Connect (OIDC) y JWT.
- Aplicar políticas de Rate Limiting, CORS, Throttling y registros de auditoría en la capa de borde.

## Consecuencias
### Positivas
- Alto rendimiento y baja latencia (basado en NGINX / OpenResty).
- Ecosistema robusto de plugins de seguridad y observabilidad.
- Soporte nativo para arquitectura Cloud-Native e integración con Kubernetes/K3s.

### Desafíos
- Curva de aprendizaje en la administración declarativa mediante decK / YAML.
